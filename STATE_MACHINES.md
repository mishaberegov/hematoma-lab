# Hematoma Lab: interaction and loading state machines (primary 0.8.6 baseline)

Scope: the browser-only primary `/hematoma-lab/` app at commit `4798cae11d23dc639a3917684c493d6195ef9d93`. This inventory describes *control state*, not anatomical accuracy. The separate `/hematoma-lab-graphcut/` implementation is not covered. State exists in DOM radios, closures, workers, arrays, and accepted-mask history; `status` text is an output, never the source of truth.

| Machine / authority | States and events | Guards / invariant | Code |
|---|---|---|---|
| Input traversal / `inputGate` | idle → reading drop → scan; new folder/files input supersedes traversal | A late directory read cannot start an older scan | `dist/input-generation.mjs`, `dist/app.mjs` drop/scan |
| DICOM scan/build / `loadState` + IO Worker | idle → scanning → choosing → building → ready; any active phase → failed; new input → scanning | At most one build in flight. Selection and Load lock during build; completed key and request ID must match. A second series can be built after ready. ## Highest-leverage decision

**Make transitions explicit at one narrow boundary at a time, starting with scan/build.** This is safer than replacing the whole viewer with a framework or one giant global reducer. The prior scan/build UI allowed Load(A) followed by Load(B) while the worker was busy; the worker dropped B, then displayed A while the chooser indicated B. `createLoadState()` now serializes builds, guards the returned key/request ID, and projects `building` into disabled controls. The worker echoes identifiers; no segmentation or DICOM decoding algorithms changed. Unit, handler-level, and synthetic two-series browser checks cover the boundary.

This improves UX (the selected series cannot silently diverge from the image), DX (pure, testable transitions), and AX (named states and executable assertions rather than inferred flags). The same incremental pattern is appropriate for the held-edit and proposal machines, **not yet migrated**. In particular, changing mode/Undo during a held pointer may still leave `holding` alive until release; cleanup status text may outlive a cancelled preview; canvas-only editing lacks a keyboard input path. Treat these as follow-up risks, not fixed behavior.

## Release gate

Before promoting this isolated change: test a real two-series synthetic DICOM ZIP on the nested app path in both languages (A then B, rapid duplicate Load, replacement input during build); rerun all Node tests and representative target/background → proposal → Accept/Undo, Grow early release → Undo, and cleanup preview → Discard/Accept. Bump all cache-pinned `?v=` imports together. Compare every published asset to the release and keep the previous symlink as rollback. Patient data stay off the Pi and site. Production is **not changed** by this inventory.
